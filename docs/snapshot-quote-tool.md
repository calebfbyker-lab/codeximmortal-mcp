# Pricing-snapshot quote tool: isolated sandbox integration

Baseline inspected: c08b9e5f0ee573c31fcf108db94a919c4fc418c2. Commercial repository increment, no CI identity or doctrine change. New code/tests are unexecuted by the assistant.

Reuses codex_service_quote -> createRequestDispatcher -> invokeMcp -> invoke -> existing backend.quote. No quote table, price engine, buyer identity system or second server implementation is created. snapshotQuoteTool supplies a real input schema; withSnapshotQuoteTool rejects duplicate names rather than replacing a broader existing quote tool. Schema marks service pricing_snapshot, sourceId only, no raw URLs, buyer IDs or caller amounts. Quote creation is neither read-only nor idempotent in the existing backend.

createSnapshotQuoteSandboxApp composes the existing createHttpApp factory with that schema and wraps the injected backend to permit only snapshot quotes. Other service quotes and submit/job/result operations are blocked in that composition. Existing buyer authentication, scope and quota paths remain. It does not bind a port; the caller is responsible for loopback/isolated test binding and synthetic dependencies. This helper is NOT a production release gate or sandbox for arbitrary injected storefront/fallback/pricing handlers. Tests inject inert handlers and bind 127.0.0.1 only.

Production http.ts, HTTP factory defaults, manifests, catalog, publication guard, environment variables, prices, deployment, payments and workers are unchanged. No public endpoint advertises the extra quote tool from this commit alone. Do not enable AGENT_COMMERCE_ENABLED or remove assertPublicationAllowed to try it. All standalone services remain planned, unpriced and unpublished. Synthetic 100-minor-unit examples are not launch prices.

Validation: npm run build; run snapshot-quote-tool.test.ts, snapshot-quote-http.integration.test.ts, existing api.test.ts, mcp-dispatch.test.ts, http-app.integration.test.ts and manifest.test.ts. New SDK integration tests use mocked auth/quote storage behind the actual HTTP app/transport. They do not establish PostgreSQL ownership or production quote correctness. Existing PostgreSQL commerce suite must run with disposable TEST_DATABASE_URL, required-database mode and acknowledgment. Further tests must verify unchanged wallet/ledger balances on quote, ownership, price/currency failures and expiry/persisted fields. Full latest-commit regression and deployment evidence remain separate.

Next increment: real PostgreSQL quote through the SDK using isolated fixtures, then reviewed release-aware production composition only after funding, provider, receipt, recovery and price approval checks. This patch does not charge, fetch a source, run a provider, submit a job or certify profitability.
